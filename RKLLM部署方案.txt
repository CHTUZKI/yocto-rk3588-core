 推荐流程
------------------------------------------------------------

  构建前准备（大文件不在 git）：
    1) deploy/rkllm/ 下 runtime 二进制
    2) 生成 Agent 依赖包：
         ./scripts/fetch-qwen-agent-aarch64.sh
       → deploy/vendor/qwen-agent-aarch64-site.tar.gz
    3) 模型仅主机保留（不进镜像）：
         deploy/models/Qwen3-4B-Instruct-2507-w8a8-rk3588.rkllm  (~4.6G)

  构建：
    source poky/oe-init-build-env build
    bitbake rk3588-image-minimal
    # 产物：build/latest/update.img（不含模型，rootfs 须 <4GiB）

  烧录：RKDevTool 刷 update.img，日志须出现 Start to download rootfsA
        核对 rootfsA size ≈ rootfs.img（约 1～2G），勿再出现 ~3G 假成功

  烧录后（等网络 / 首启 resize2fs）：
    ping 192.168.1.14
    ssh root@192.168.1.14 'mkdir -p /opt/models'
    scp deploy/models/Qwen3-4B-Instruct-2507-w8a8-rk3588.rkllm \
        root@192.168.1.14:/opt/models/
    # 建议校验大小后再启服务：
    #   ssh root@192.168.1.14 'ls -lh /opt/models/'
    ssh root@192.168.1.14 'systemctl start rkllm-server'
    # 模型加载可能需数分钟；TimeoutStartSec=600
    curl -sS http://192.168.1.14:8080/v1/models
    ls -lh 经 ssh：/opt/models /opt/rkllm /opt/rkllm_server /opt/qwen_agent

  PC 客户端：
    cd rk3588-agent-chat && ./run.sh

------------------------------------------------------------
 踩坑摘要
------------------------------------------------------------

  1. rootfsA:grow → RKDevTool 不写 rootfs（改固定 0x03A00000）
  2. mmc CQE → 大文件写 eMMC 易卡死（设备树删 supports-cqe）
  3. 模型与 runtime 版本对齐：RKLLM 1.2.3 + NPU 0.9.8
  4. 大文件 SCP 中断可导致 EXT4 journal abort → 无法挂载 root → 需重刷
     （SCP 时尽量稳定供电与网络；传完核对文件大小约 4.6G）
  5. update.img 单分区镜像 >4GiB：afptool/RKDevTool uint32 截断，
     烧录显示成功但 rootfs 损坏（No working init / EXT4 checksum）

主机备份：
  build/latest/update.img
  deploy/models/  deploy/rkllm/  deploy/vendor/
